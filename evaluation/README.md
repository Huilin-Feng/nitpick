# Evaluation

A small, reproducible benchmark for nitpick. Each case is a diff with
one planted issue (or none, for clean PRs), so results can be scored
automatically.

## Layout

```
evaluation/
├── fixtures/<case>/before/   code before the change
├── fixtures/<case>/after/    code after the change
├── diffs/<case>.diff         generated by build_diffs.py
├── cases.json                expected issues per case
├── scoring.py                matching and metrics (unit tested)
├── run_eval.py               runs the reviewer and reports results
└── results/                  saved runs, one JSON file per experiment
```

## Cases

| Group | Cases |
| --- | --- |
| Bug | off-by-one, mutable default, swallowed exception, unclosed file, `None` access, `is` comparison |
| Security | SQL injection, hard-coded API key, shell injection |
| Performance | N+1 queries, list membership in a loop |
| Clean | rename only, docstrings only, tests only |
| Hard | stale caller in another file, bug in the last hunk of a large file |

## Metrics

- **Recall**: planted issues found / planted issues
- **Strict precision**: comments matching a planted issue / all comments on non-clean cases
- **False positives per clean PR**: comments on PRs that need none
- **Validity**: comments kept / (kept + dropped for pointing outside the diff)
- **Cost and latency** per review

A comment matches an issue if it is on the same file and within
`--tolerance` lines (default 3) of an accepted location. Each case runs
`--runs` times (default 3) because LLM output varies between calls.

Strict precision undercounts: a comment that points out a real problem
we did not plant counts as wrong. Saved results include every comment,
so these can be reviewed by hand.

## Usage

```bash
python -m evaluation.build_diffs              # after editing fixtures
python -m evaluation.run_eval --dry-run       # free pipeline check
python -m evaluation.run_eval --label baseline
```
